# Review

## 目标

在固定范围内识别仍然存在的 legacy 实现或兼容路径，只报告有证据支持的
findings，不修改既有 repository artifact，也不产生 external mutation。

## 契约

- 当前代码和实际调用关系是实现状态的主要证据。
- 当前公开契约、配置、测试、构建入口和可重复运行结果用于判断行为是否仍被需要。
- 工作树中的既有修改属于用户；必须识别并保留，不能把它们误判为死代码。
- 历史记录可以解释背景，但不自动构成当前 runtime contract，也不能仅因记录过去
  决策而被判定为 legacy。
- 名称、注释、文件年龄、代码风格和理论上的简化空间都不足以支持删除。
- 检索优先覆盖 Git tracked files 和固定范围内的工作树修改，包括相关未跟踪文件。
  默认排除 Git ignored 缓存、构建产物、依赖目录和范围外的未跟踪目录；只有调用关系、
  构建入口或契约证据指向这些位置时才扩展检索。

## 流程

1. 固定用户指定的目录、模块、提交差异或文件范围，并检查当前工作树。
2. 在范围内寻找用户点名的候选，以及旧类型、旧 schema、adapter、deprecated
   API、兼容路径、fallback、双执行路径、未调用代码和失效测试或文档。
3. 对每个候选检查定义、直接调用方、间接入口、构建或配置引用、公开契约和相关
   运行证据。文本搜索只能发现候选，不能代替调用关系。
4. 将候选判定为：
   - `finding`：证据证明它已被替代、不可达、重复或与当前契约冲突；
   - `required`：仍被调用，或由当前契约和现实数据明确要求；
   - `undetermined`：现有证据不足以安全判断。
5. 只运行不修改既有 repository artifact 或 external state 的检查、测试、构建和 live
   observation。生成输出只能进入新建临时目录，或仓库明确指定的 disposable build/test
   目录；不得覆盖其他既有 untracked 或 ignored artifact。完成后复核工作树。
   如果完成判定所必需的证据只能通过 external mutation 取得，保持 `undetermined`，
   说明缺少的证据并请求独立验证授权。

## 报告

先按影响程度列出 findings。每项包含：

- 本次 review 内唯一的 ID，例如 `LP-01`；
- 准确位置；
- 调用关系、现实消费者以及是否可以直接删除；
- 当前行为及影响；
- 判定所依据的代码、契约或运行证据；
- 目标状态，包括应保留的唯一当前路径或应完整删除的能力；
- 允许删除或更新的边界；
- 预期验证；
- 推荐的最小修改。

随后简要列出已检查但确认必须保留的候选、无法确定的限制，以及执行过的验证。
如果没有 findings，明确说明，并报告仍存在的证据盲区。

完成报告后停止，不实施修复。
